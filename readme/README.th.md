**Baton คือระบบส่งต่อโปรเจกต์แบบวิ่งผลัด** ที่ให้ Claude Code, Codex, Cursor และ DeepSeek Harness ผลัดกันดูแล**โปรเจกต์เดียวกัน**ข้ามเครื่อง — ความคืบหน้า ความจำ สเปกดีไซน์ งาน และ Git คงเส้นคงวา **คุณพูดตามปกติ ส่วนที่เหลือมันจัดการเอง**

**คำมั่นสัญญาหลักสามข้อ:**

1. **🔄 ใครก็รับช่วงต่อได้** — เปลี่ยนเครื่องมือ AI หรือเครื่อง แล้วพูดคำสั่งเดียว ก็ไปต่อจากจุดเดิมได้ทันที ไม่ต้องอธิบายโปรเจกต์ใหม่
2. **🎯 ทำตามที่สั่ง** — ขอบเขตงานและเส้นทางที่ป้องกันถูกตรวจเชิงกลตอนปิดงาน และข้อเท็จจริงด้านดีไซน์ถูกล็อกไว้ในสเปก ส่วนที่เหลือมีกฎและการรีวิวคุม — ความเพี้ยนถูกจับได้ ไม่ใช่เพิ่งมาเจอทีหลังหลายชั่วโมง
3. **✅ "เสร็จ" หมายถึงเสร็จจริง** — ตอนปิดงาน commit, push และ**ตรวจ SHA ฝั่งรีโมต**ให้อัตโนมัติ — ไม่มีอีกแล้วกับ "commit ในเครื่องแล้วแต่ไม่ขึ้น GitHub แต่กลับบอกว่าเสร็จ"

## 🚀 เริ่มต้นอย่างรวดเร็ว (DeepSeek Harness — บรรทัดเดียว)

> ใช้ DeepSeek Harness อยู่ใช่ไหม? นี่คือทั้งหมดที่ต้องทำ

```powershell
dsh plugin --profile web add @kakadeka/dsh-baton
```

1. ติดตั้ง DSH CLI ครั้งเดียว: `npm i -g @deepseek-ai/dsh`
2. วางบรรทัดข้างบนแล้วกด Enter
3. รีสตาร์ต `dsh` — เสร็จ เครื่องมือ `baton_*` ทั้ง 16 ตัวทำงานในโปรไฟล์ของคุณแล้ว

> ติดตั้งจาก GitHub ก็ได้: `dsh plugin --profile web add github:kakadeka/Baton`
> ใช้ **Codex / Claude Code / Cursor** แทนหรือเปล่า? ไปที่[การติดตั้งสำหรับเครื่องมือ AI อื่น](#-install-for-other-ai-tools-codex--claude--cursor)

| # | ปัญหา | คำตอบของ Baton |
|---|---|---|
| 1 | ทุกเช้าหรือเครื่องใหม่: ใช้สาขาไหน? เมื่อวานทำอะไร? รีโมตอัปเดตแล้วหรือยัง? | พูด **clock in** — ตรวจ git อัตโนมัติ + ซิงก์ปลอดภัย + อ่านแฮนด์ออฟ/งาน → ตารางงาน → ตอบเลข |
| 2 | "commit ในเครื่องแต่ไม่ push"; มานั่งรัน git ด้วยมือตอนดึก | พูด **clock out** — ตรวจสอบ → เอกสาร/ความจำ/เมตริก → commit → push → **SHA รีโมต == HEAD ในเครื่อง ก่อนถึงจะ "เสร็จ"** |
| 3 | "งานเสร็จ" กับ "ปิดงานวัน" มันปนกัน | พูด **complete task** — ปิดงาน บันทึกผล เสนองานถัดไป งานเสร็จ ≠ ปิดงานวัน |
| 4 | ดีไซน์ที่ยืนยันแล้วถูกลืม AI แต่งเองมั่ว | พูด **save design spec** — ล็อกข้อเท็จจริงดีไซน์ลงสเปกถาวร (กรณีขัดแย้งเก็บประวัติไว้) งาน UI อ้างอิงให้อัตโนมัติ |
| 5 | เซสชันหาย บทสนทนาใหม่ ต้องอธิบายใหม่หมด | พูด **continue work** — กู้คืนงาน/สาขา/ตัวบล็อก/แฮนด์ออฟ/ขั้นถัดไป ประโยคเดียวจบ |
| 6 | งานหลายชิ้น AI ไม่ควรเลือก priority เอง พิมพ์งานเต็ม ๆ น่าเบื่อ | ตารางงานมีเลข — ตอบ `1`/`2`/`3` |
| 7 | โปรเจกต์ยาว ประวัติตามไม่ทัน อ่านใหม่หมดเปลือง token | การตัดสินใจ/หลุมพราง/สเปก ถูกทำดัชนีอัตโนมัติ **ค้นดัชนีก่อน อ่านเฉพาะส่วนที่เจอ** |
| 8 | ผลัดกันระหว่าง Codex/Claude/Cursor โดยไม่รู้ว่าคนก่อนทำอะไร | ไฟล์แฮนด์ออฟเดียว — สาขา/HEAD/สิ่งที่แก้/ข้อจำกัด/ขั้นถัดไป อ่านรายการล่าสุดแล้วไปต่อ |
| 9 | โมเดลแพงใช้กับทุกอย่าง โมเดลถูกทำผิดบ่อย สลับเองก็เจ็บ | เราเตอร์โมเดลอัตโนมัติตามความยาก — micro: เซสชันหลัก, ปกติ: flash, ซับซ้อน/รีวิว: pro พร้อมสายสำรอง |
| 10 | "จริง ๆ แล้วโมเดลไหนทำงาน?" บิลไม่ตรง | บันทึก recommended กับ actual แยกกัน ระบุแหล่งที่มาอย่างซื่อตรง (บันทึกการส่งงาน / ตัวระบุโฮสต์ / ไม่ทราบ) |
| 11 | AI เพี้ยนออกจากต้นแบบหลังทำงานไปหลายชั่วโมง | ข้อกำหนดแช่แข็ง + เส้นทางอนุญาต/ป้องกัน + ตรวจขอบเขตเชิงกล + รีวิวอิสระ + ไม่มี git อันตราย |
| 12 | เปลี่ยนสีปุ่มปุ่มเดียวใช้เวลาเป็นชั่วโมง | ทางด่วน micro — ไม่ส่งต่องาน ไม่มี reviewer ไม่มีเทสที่ไม่เกี่ยวข้อง งานง่ายใช้เวลาไม่กี่นาที |
| 13 | งานซับซ้อนต้องไม่ทำแบบลวก ๆ | ด่านที่เข้มขึ้นตามลำดับ: สัญญา, โมเดลแกร่ง, reviewer อิสระ, fidelity เทียบสเปกแช่แข็ง, แผนย้อนกลับ |
| 14 | เครื่องออฟฟิศกับบ้านซิงก์ไม่ตรง กลัวงานในเครื่องหาย | fetch ปลอดภัย + ซิงก์แบบ ff-only (ไม่เขียนทับเด็ดขาด), commit/push อัตโนมัติ, ตรวจ SHA รีโมต; force/reset/clean ถูกห้าม |
| 15 | เลือกโมเดลตามความรู้สึก ไม่มีข้อมูลจริง | ทุกงานบันทึกโมเดลจริงและการเสร็จงาน → แดชบอร์ดรายเดือน; สำเร็จ/ล้มเหลว/ระยะเวลาที่ยังไม่เก็บ แสดงเป็น "ไม่บันทึก" ไม่แต่งขึ้น |
| 16 | อยากนำระบบไปใช้/แชร์กับโปรเจกต์ใหม่ | เฟรมเวิร์กกับอินสแตนซ์โปรเจกต์แยกขาดจากกัน; `Baton init` เซ็ตอัปครั้งเดียว; แชร์ผ่านไปป์ไลน์ทำความสะอาด (ไม่มีคีย์/เส้นทาง/โน้ตส่วนตัว) |
| 17 | มีสกิลอื่นติดตั้งอยู่แล้วข้ามกฎของโปรเจกต์ | สกิลภายนอกช่วยได้ แต่ขอบเขตโปรเจกต์ (เส้นทาง, สเปกดีไซน์, วินัย git) ถูกบังคับโดย Baton ประสานกับ AGENTS.md |

## ✨ ฟีเจอร์ (8 บล็อกความสามารถ)

- **คำสั่งอัตโนมัติ** — clock in / clock out / continue work / save design spec / complete task / update project docs / remember / Baton init / ยืนยันด้วยเลข / git ภาษาธรรมชาติ
- **ข้าม AI และข้ามเครื่อง** — ความจริงของโปรเจกต์แบบข้อความล้วน + อะแดปเตอร์บาง ๆ คำสั่งเดียว (Codex/Claude/Cursor) + ส่งต่อแบบวิ่งผลัด
- **ความจำระยะยาว** — การตัดสินใจ/หลุมพราง/สเปก เก็บถาวรอัตโนมัติ + ดัชนีเบา ๆ อ่านแบบค่อยเป็นค่อยไป ไม่ต้องอ่านใหม่หมด
- **กันเพี้ยน** — ข้อจำกัดแช่แข็ง + ตรวจเส้นทางอนุญาต/ป้องกัน + รายการการเปลี่ยนแปลงต้องห้าม + รีวิวอิสระ + ไม่มี git อันตราย
- **วงจรความจริงของ Git** — ซิงก์ ff-only, commit/push อัตโนมัติ, **SHA รีโมต == HEAD ในเครื่อง**, บันทึกการเผยแพร่ (`last_published_sha`)
- **เราเตอร์โมเดลอัตโนมัติ** — ระดับงาน × ตารางกฎ (flash/pro + สูง/สูงสุด + สำรอง); บันทึก recommended กับ actual อย่างโปร่งใส
- **แดชบอร์ดรายเดือน** — จัดอันดับโมเดล / กิจกรรมรายชั่วโมง / รายละเอียดรายวัน / รายละเอียดเอเจนต์ จากข้อมูลการทำงานจริง
- **ตรวจรับคลิกเดียว** — `baton_accept`: ตรวจโครง/สถานะ/ความปลอดภัย/ขนาด → PASS/FAIL + รายการตัวบล็อก

## 🗣️ คำสั่ง (ใช้ตอนไหนบ้าง)

พูดวลีภาษาอังกฤษใดก็ได้ต่อไปนี้ — ความหมายเหมือนกันในทุก AI ผู้ใช้ภาษาจีนใช้คำสั่งจีนได้ (ดูเวอร์ชันจีนที่ลิงก์ด้านบน)

| คำสั่ง | เมื่อไหร่ | จะเกิดอะไรขึ้น |
|---|---|---|
| **clock in** / *start work* | เริ่มวัน / เครื่องใหม่ / AI ใหม่ | ตรวจ git → ซิงก์ปลอดภัย → แฮนด์ออฟและงาน → ตารางงาน |
| **clock out** / *end work* | จบวันทำงาน | ตรวจสอบ → เอกสาร/ความจำ/เมตริก → commit → push → **ตรวจ SHA รีโมต** |
| **continue work** / *resume* | เซสชันหาย / เปลี่ยนเครื่องมือ | กู้คืนงาน สาขา ตัวบล็อก ท้ายแฮนด์ออฟ ขั้นถัดไป |
| **save design spec** | หลังจากคุณยืนยันดีไซน์ | ล็อกลงสเปกถาวร + ดัชนี งาน UI ทำตาม |
| **complete task** | งานหนึ่งเสร็จแล้วยังมีต่อ | ปิดงาน บันทึกผล เสนอขั้นถัดไป (ไม่ใช่ปิดงานวัน) |
| **update project docs** | จุดเช็กระหว่างทำงาน | เขียนความคืบหน้า + จุดเช็คแฮนด์ออฟ (พื้นที่ทำงานยังถูกยึดอยู่) |
| **remember this pitfall** / *record this decision* | เจอหลุมพราง / ตัดสินใจแล้ว | เขียนลงความจำระยะยาว + ทำดัชนีอัตโนมัติ |
| **Baton init** | ครั้งแรกในโปรเจกต์ใหม่ | สร้างโครงความจำ + คอนฟิก (ไม่เขียนทับเด็ดขาด) |
| ตอบ `1` / `2` / `3` | ตารางงานแสดงแล้ว | เลขถูกบันทึกเป็นงานปัจจุบัน แล้วเริ่มทำงาน |
| **release workspace** / *I confirm the previous agent stopped* | ขัดแย้งการถือครองตอนเข้าทำงาน | ปลดล็อกตัวเขียนคนเดียว + เขียนบันทึกการปล่อย |
| **pull github** / *sync github* / *check git status* | ตั้งใจใช้ git เอง | เส้นทาง git เบา ๆ ไม่มีพิธีสัญญา/รีวิว |
| **check update** | มี Baton เวอร์ชันใหม่ไหม? | อ่านเวอร์ชันแองเคอร์ในเครื่อง + ตรวจสอบเวอร์ชันล่าสุดจาก GitHub/npm แล้วรายงานผล |
| **update baton** / *upgrade baton* | มีเวอร์ชันใหม่ออก | AI ดำเนินการอัปเดตทั้งหมด (git pull + ติดตั้งซ้ำ / npm update) และตรวจสอบว่าเครื่องตรงกับรีโมต |

## 🛠️ การติดตั้งสำหรับเครื่องมือ AI อื่น (Codex / Claude / Cursor)

> **ติดตั้ง = คัดลอกหนึ่งคำสั่ง กด Enter รอให้เสร็จ แล้วตรวจด้วยคำสั่งเดียว** ไม่ต้องสร้างโฟลเดอร์เอง ไม่ต้องคัดลอกไฟล์เอง
> ผู้ใช้ DeepSeek Harness ข้ามส่วนนี้ได้ — ใช้ quick start ด้านบนแทน

### ขั้นที่ 0: ตัดสินใจว่าต้องติดตั้งแบบไหน (10 วินาที)

| สถานการณ์ของคุณ | ติดตั้งแบบนี้ | หลังติดตั้ง |
|---|---|---|
| หลายโปรเจกต์ — อยากให้ Baton ใช้ได้ใน**ทุกโปรเจกต์บนเครื่องนี้** | **ระดับผู้ใช้** (ครั้งเดียวต่อเครื่อง) | ใช้ได้ทั้งเครื่อง โปรเจกต์ไหนก็รู้จักคำสั่ง |
| **โปรเจกต์เฉพาะ**ที่อยากให้เครื่องอื่น/AI อื่นมารับช่วง | **ระดับโปรเจกต์** (ครั้งเดียวต่อโปรเจกต์) | โปรเจกต์พกโครงความจำ + อะแดปเตอร์ 3 เครื่องมือไปด้วย `git clone` แล้วไปต่อ |
| ทั้งสองอย่าง | ระดับผู้ใช้ก่อน แล้วระดับโปรเจกต์ | ครบที่สุด |

> 💡 **แนะนำ**: รันระดับผู้ใช้ (30 วิ) แล้วรันระดับโปรเจกต์กับโปรเจกต์จริงของคุณ (30 วิ)

### ขั้นที่ 1: ดาวน์โหลด Baton (ครั้งเดียว)

เปิด PowerShell (กด `Win` พิมพ์ `powershell` Enter) แล้ววางบรรทัดนี้:

```powershell
git clone https://github.com/kakadeka/Baton.git $HOME\Baton
```

> ไม่มี git? ติดตั้งจาก https://git-scm.com/download/win เปิด PowerShell ใหม่แล้ววางอีกครั้ง

### ขั้นที่ 2: เลือกแบบติดตั้งแล้ววางคำสั่ง

**ตัวเลือก A — ระดับผู้ใช้ (ครั้งเดียวต่อเครื่อง ทุกโปรเจกต์)**

```powershell
pwsh -File $HOME\Baton\scripts\baton-install.ps1 -Scope User
```

จะเห็น `ok: [Codex] ...`, `ok: [Claude Code] ...`, `ok: [Cursor] ...` — สกิลส่วนกลางของเครื่องมือ AI ทั้งสามติดตั้งแล้ว

**ตัวเลือก B — ระดับโปรเจกต์ (ครั้งเดียวต่อโปรเจกต์ ทำให้โปรเจกต์พกพาได้)**

```powershell
cd C:\your\project\path
pwsh -File $HOME\Baton\scripts\baton-install.ps1 -Scope Project
```

จะเห็นบรรทัดสำเร็จ (ติดตั้งระดับโปรเจกต์เสร็จสิ้น) พร้อมรายการที่สร้าง (โครงความจำ `docs/ai_memory`, คอนฟิก `.baton`, สกิลมิเรอร์สามตัว และรายการใน `AGENTS.md` / `CLAUDE.md` / `.cursorrules`) ถ้าบอกว่าไม่มี `.git` ให้รันคำสั่ง `git init` ที่มันพิมพ์ออกมา

> การติดตั้งระดับโปรเจกต์อัตโนมัติเต็มรูปแบบ และ**ทำงานได้โดยไม่ต้องมีปลั๊กอิน DeepSeek Harness** (โหมดไร้ปลั๊กอิน)

### ขั้นที่ 3: ตรวจสอบ (สำคัญที่สุด — คำสั่งเดียว)

ในโปรเจกต์ บอก AI ของคุณว่า:

```
clock in
```

**✅ สำเร็จ**: AI ทำตาม Baton และแสดงรายงานสถานะพร้อมสาขา, HEAD, สถานะ working tree, งานปัจจุบัน และสรุปแฮนด์ออฟ ตามด้วยตารางงาน เช่น —

```
Task table: 1) ...
```

**❌ ไม่มีอะไรเกิดขึ้น?** ตรวจตามลำดับ:

1. คุณใช้ AI ตัวไหน? Claude Code → `~\.claude\skills\baton\SKILL.md`; Codex → `~\.agents\skills\baton\SKILL.md`; Cursor → `~\.cursor\skills\baton\SKILL.md` (การติดตั้งระดับผู้ใช้สร้างครบทั้งสาม)
2. โปรเจกต์มี `.git` ไหม? (ถ้าไม่มี `git init` + commit แรก)
3. คำสั่งคือ **clock in** เป๊ะ ๆ ไม่มีอะไรต่อท้ายใช่ไหม?
4. โปรเจกต์มี `docs/ai_memory/` ไหม? (การติดตั้งระดับโปรเจกต์สร้างให้)

### ขั้นที่ 4: เข้าร่วมโปรเจกต์ Baton ที่มีอยู่แล้ว (เครื่องใหม่ / AI ใหม่)

บนเครื่องใหม่: ติดตั้ง git → `git clone` โปรเจกต์ของคุณ → บอก AI ของคุณว่า:

```
clock in  หรือ  continue work
```

ความจำ แฮนด์ออฟ และงานมากับโค้ด ไปต่อได้เลย — ไม่ต้องติดตั้งอะไรเพิ่ม

### สคริปต์คลิกเดียวทำอะไรบ้าง (โปร่งใส)

| โหมด | ทำอัตโนมัติ |
|---|---|
| ระดับผู้ใช้ | คัดลอก `SKILL.md` ไปยังโฟลเดอร์สกิลส่วนกลางของเครื่องมือ AI ทั้งสาม (Codex / Claude Code / Cursor) |
| ระดับโปรเจกต์ | ① โครง `docs/ai_memory/` (พร้อมบันทึกรีวิชัน + ดัชนีถาวร) ② `.baton/config.json` ③ ต่อท้าย `.gitignore` ④ สกิลมิเรอร์สามตัว ⑤ ส่วนหัวสามไฟล์ (`AGENTS.md` / `CLAUDE.md` / `.cursorrules` ไม่เขียนทับกฎของคุณเด็ดขาด) |

รันซ้ำได้อย่างปลอดภัย: การรันซ้ำไม่เขียนทับเอกสารและกฎที่มีอยู่เด็ดขาด มันแค่เติมส่วนที่ขาด

## 📁 ความจริงอยู่ที่ไหน

```
project/
├── docs/ai_memory/            ← ความจำระยะยาว (ซิงก์กับ Git, ไม่ผูกกับ AI เจ้าใด)
│   ├── index.md               ← อ่านฉันก่อน
│   ├── current.md             ← ตอนนี้เกิดอะไรขึ้น
│   ├── handoff_current.md     ← บันทึกแฮนด์ออฟ (รายการล่าสุด = ความจริง)
│   ├── state/                 ← tasks.json, archive_index.json, project_state.json
│   ├── knowledge/             ← tech_decision.md, pit_experience.md
│   ├── ui_spec/               ← สเปกดีไซน์
│   ├── daily_log/             ← บันทึกรายวัน
│   └── agent_metrics/YYYY/MM/index.html  ← แดชบอร์ดรายเดือน
└── .baton/                    ← เฉพาะเครื่องนี้ (gitignored ยกเว้น config.json): คอนฟิก, เมตริก, หลักฐาน
```

## 🛡️ ความปลอดภัยและหลักการออกแบบ

- git อันตราย (force push / reset --hard / clean เสี่ยง / rebase ที่ไม่ได้รับอนุญาต) ไม่มีอยู่จริง
- การซิงก์เป็น ff-only เท่านั้น ถ้าแยกกันจะหยุดและรายงาน ไม่แก้คอนฟลิกต์อัตโนมัติเด็ดขาด
- ข้อมูลรับรองไม่เข้า Git / ความจำ / เมตริก / ล็อก เด็ดขาด
- ประวัติแก้ไขแบบต่อท้ายอย่างเดียว หรือทำเครื่องหมาย "ถูกแทนที่" — ไม่เขียนทับเด็ดขาด
- "เสร็จ" = หลักฐานเชิงกล (SHA รีโมต + บันทึกการเผยแพร่) ไม่ใช่คำกล่าวอ้าง
- ประหยัด token เป็นเป้าหมายอันดับหนึ่ง: ดัชนีก่อน, โมเดลตามความเสี่ยง, เอาต์พุตมีขอบเขต, ไม่เรียกซ้ำซ้อน
