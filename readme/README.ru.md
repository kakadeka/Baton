**Baton — это система эстафетной совместной работы над проектами.** Она позволяет Claude Code, Codex, Cursor и DeepSeek Harness по очереди поддерживать **один и тот же проект** на разных машинах — прогресс, память, дизайн-спецификации, задачи и Git остаются согласованными. **Вы говорите обычными словами; остальное делает она.**

**Три ключевых обещания:**

1. **🔄 Подхватить может кто угодно** — смените ИИ-инструмент или машину, скажите одну команду и продолжите ровно с того места, где остановились. Без повторного объяснения проекта.
2. **🎯 Делать то, что просили** — границы задач и защищённые пути механически проверяются при закрытии, а факты дизайна фиксируются в спецификациях; остальное охраняют правила и ревью — отклонение ловится, а не обнаруживается спустя часы.
3. **✅ «Готово» действительно означает готово** — закрытие само делает commit, push и **проверяет удалённый SHA** — больше никаких «закоммитил локально, но не на GitHub, а говорят, что готово».

## 🚀 Быстрый старт (DeepSeek Harness — одна строка)

> Пользуетесь DeepSeek Harness? Это всё, что нужно.

```powershell
dsh plugin --profile web add @kakadeka/dsh-baton
```

1. Один раз установите CLI DSH: `npm i -g @deepseek-ai/dsh`
2. Вставьте строку выше и нажмите Enter.
3. Перезапустите `dsh` — готово. Все 16 инструментов `baton_*` уже активны в вашем профиле.

> Можно установить и с GitHub: `dsh plugin --profile web add github:kakadeka/Baton`
> Используете **Codex / Claude Code / Cursor**? Перейдите к [установке для других ИИ-инструментов](#-install-for-other-ai-tools-codex--claude--cursor).

## 📖 Сценарии (по одному на требование: боль → ответ Baton)

| # | Боль | Ответ Baton |
|---|---|---|
| 1 | Каждое утро или новая машина: какая ветка? что сделано вчера? обновлён ли remote? | Скажите **clock in** — авто-проверки git + безопасная синхронизация + чтение handoff и задач → таблица задач → ответьте номером |
| 2 | «Закоммичено локально, но не запушено»; ручной PowerShell-git по вечерам | Скажите **clock out** — проверка → документы/память/метрики → commit → push → **удалённый SHA == локальный HEAD до слова «готово»** |
| 3 | «Задача готова» и «конец дня» перепутались | Скажите **complete task** — закройте задачу, запишите результат, предложите следующее. Задача готова ≠ конец дня |
| 4 | Подтверждённые дизайны забываются; ИИ импровизирует | Скажите **save design spec** — зафиксируйте факты дизайна в долгосрочных спецификациях (конфликты сохраняют историю); UI-задачи ссылаются на них автоматически |
| 5 | Сессия потеряна, новый разговор — объяснять всё заново | Скажите **continue work** — восстановите задачу/ветку/блокер/handoff/следующий шаг. Одна фраза — готово |
| 6 | Несколько задач; ИИ не должен решать приоритеты; набирать задачи целиком утомительно | Таблица задач с номерами — ответьте `1`/`2`/`3` |
| 7 | Длинный проект, история недоступна; перечитывать всё — жечь токены | Решения/грабли/спецификации авто-индексируются; **спросите индекс, читайте только найденный фрагмент** |
| 8 | Эстафета Codex/Claude/Cursor без понимания, что сделал предыдущий | Единый файл handoff — ветка/HEAD/изменения/ограничения/следующий шаг. Прочтите последнюю запись и продолжайте |
| 9 | Дорогая модель для всего; слабая ошибается; ручное переключение мучительно | Авто-маршрутизация моделей по сложности — micro: главная сессия, обычная: flash, сложная/ревью: pro, с цепочками запасных |
| 10 | «Какая модель реально работала?» счета не сходятся | recommended и actual записываются раздельно, источник честно помечается (запись диспетчеризации / дескриптор хоста / неизвестно) |
| 11 | ИИ отклонился от прототипа после часов работы | Замороженные требования + разрешённые/защищённые пути + механические проверки объёма + независимое ревью + никакого опасного git |
| 12 | Смена цвета кнопки заняла час | Быстрый путь micro — без делегирования, без ревьюера, без лишних тестов. Простые задачи занимают минуты |
| 13 | Сложные задачи нельзя делать спустя рукава | Нарастающие барьеры: контракт, сильная модель, независимый ревьюер, fidelity против замороженной спецификации, план отката |
| 14 | Офисная и домашняя машины рассинхронизированы; страх потерять локальную работу | Безопасный fetch + синхронизация ff-only (никогда не перезаписывает), авто commit/push, проверка удалённого SHA; force/reset/clean запрещены |
| 15 | Выбор моделей на ощупь, без реальных данных | Каждая задача фиксирует реальную модель и завершение → месячный дашборд; ещё не собранные успех/провал/длительность показываются как «не записано», никогда не выдумываются |
| 16 | Переиспользовать/поделиться системой с новым проектом | Фреймворк и экземпляр проекта полностью разделены; `Baton init` — одноразовая инициализация; публикация через очищающий пайплайн (без ключей/путей/приватных заметок) |
| 17 | Установлены другие скиллы в обход правил проекта | Внешние скиллы могут помогать, но границы проекта (пути, дизайн-спецификации, дисциплина git) обеспечивает Baton, согласованно с AGENTS.md |

## ✨ Возможности (8 блоков)

- **Автоматизация команд** — clock in / clock out / continue work / save design spec / complete task / update project docs / remember / Baton init / подтверждение номером / git на естественном языке
- **Кросс-ИИ и кросс-машинность** — проектная истина в простом тексте + тонкие адаптеры одной командой (Codex/Claude/Cursor) + эстафета через handoff
- **Долговременная память** — решения/грабли/спецификации авто-архивируются + лёгкий индекс; постепенное чтение, без полного перечитывания
- **Защита от отклонений** — ЗАМОРОЖЕННЫЕ ограничения + проверки разрешённых/защищённых путей + список запрещённых изменений + независимое ревью + никакого опасного git
- **Петля истины Git** — синхронизация ff-only, авто commit/push, **удалённый SHA == локальный HEAD**, запись о публикации (`last_published_sha`)
- **Авто-маршрутизация моделей** — уровень задачи × таблица правил (flash/pro + высокий/макс + запасной); recommended и actual записываются прозрачно
- **Месячный дашборд** — рейтинг моделей / активность по часам / дневная детализация / детализация по агентам из реальных данных выполнения
- **Приёмка в один клик** — `baton_accept`: проверки скелета/состояния/безопасности/объёма → PASS/FAIL + список блокировок

## 🗣️ Команды (когда какую использовать)

Скажите любую из этих английских фраз — смысл одинаков для любого ИИ. Китайские триггеры — в китайской версии (ссылка вверху).

| Команда | Когда | Что происходит |
|---|---|---|
| **clock in** / *start work* | начало дня / новая машина / новый ИИ | проверки git → безопасная синхронизация → handoff и задачи → таблица задач |
| **clock out** / *end work* | конец рабочего дня | проверка → документы/память/метрики → commit → push → **проверка удалённого SHA** |
| **continue work** / *resume* | потеряна сессия / сменён инструмент | восстановить задачу, ветку, блокер, конец handoff, следующий шаг |
| **save design spec** | после подтверждения дизайна | зафиксировать в долгосрочной спецификации + индекс; UI-задачи её соблюдают |
| **complete task** | задача готова, есть ещё дела | закрыть задачу, записать результат, предложить следующее (без полного закрытия) |
| **update project docs** | контрольная точка посреди работы | записать прогресс + контрольную точку handoff (рабочая область остаётся занятой) |
| **remember this pitfall** / *record this decision* | наступили на грабли / приняли решение | записать в долговременную память + авто-индекс |
| **Baton init** | первый раз в новом проекте | сгенерировать скелет памяти + конфигурацию (никогда не перезаписывает) |
| ответьте `1` / `2` / `3` | показана таблица задач | номер сохраняется как текущая задача, затем начинается работа |
| **release workspace** / *I confirm the previous agent stopped* | конфликт владения при входе | снять блокировку единственного писателя + записать заметку об освобождении |
| **pull github** / *sync github* / *check git status* | ручное намерение по git | лёгкий git-путь, без церемоний контракта/ревью |
| **check update** | Есть ли новая версия Baton? | Прочитать локальный якорь версии + запросить последнюю версию из GitHub/npm и сообщить результат |
| **update baton** / *upgrade baton* | Вышла новая версия | ИИ выполняет полное обновление (git pull + повторный запуск установки / npm update) и проверяет локальная == удалённая |

## 🛠️ Установка для других ИИ-инструментов (Codex / Claude / Cursor)

> **Установка = скопировать одну команду, нажать Enter, дождаться завершения, затем проверить одной командой.** Никакого ручного создания папок и копирования файлов.
> Пользователи DeepSeek Harness могут пропустить этот раздел — используйте быстрый старт выше.

### Шаг 0: Решите, какая установка вам нужна (10 секунд)

| Ваша ситуация | Ставьте это | После установки |
|---|---|---|
| Несколько проектов — нужен Baton в **каждом проекте на этой машине** | **Пользовательский уровень** (один раз на машину) | Глобально на этой машине; любой проект распознаёт команды |
| Один **конкретный проект**, который должны подхватить другие машины/ИИ | **Уровень проекта** (один раз на проект) | Проект несёт свой скелет памяти + адаптеры трёх инструментов; `git clone` и продолжайте |
| И то и другое | Сначала пользовательский, затем проектный | Наиболее полно |

> 💡 **Рекомендуется**: выполните пользовательский уровень (30 с), затем проектный на вашем реальном проекте (30 с).

### Шаг 1: Скачайте Baton (один раз)

Откройте PowerShell (нажмите `Win`, введите `powershell`, Enter) и вставьте эту строку:

```powershell
git clone https://github.com/kakadeka/Baton.git $HOME\Baton
```

> Нет git? Установите с https://git-scm.com/download/win, заново откройте PowerShell и вставьте снова.

### Шаг 2: Выберите тип установки и вставьте его команду

**Вариант A — Пользовательский уровень (один раз на машину, все проекты)**

```powershell
pwsh -File $HOME\Baton\scripts\baton-install.ps1 -Scope User
```

Вы увидите `ok: [Codex] ...`, `ok: [Claude Code] ...`, `ok: [Cursor] ...` — глобальный скилл для всех трёх ИИ-инструментов установлен.

**Вариант B — Уровень проекта (один раз на проект, делает проект переносимым)**

```powershell
cd C:\your\project\path
pwsh -File $HOME\Baton\scripts\baton-install.ps1 -Scope Project
```

Вы увидите строку успеха (установка на уровне проекта завершена) и список созданного (скелет памяти `docs/ai_memory`, конфигурация `.baton`, три зеркала скилла и записи в `AGENTS.md` / `CLAUDE.md` / `.cursorrules`). Если скажет, что нет `.git`, выполните выведенные им команды `git init`.

> Установка на уровне проекта полностью автоматическая и **работает без плагина DeepSeek Harness** (режим без плагина).

### Шаг 3: Проверьте (самое важное — одна команда)

В проекте скажите вашему ИИ:

```
clock in
```

**✅ Успех**: ИИ действует по Baton и выводит отчёт о состоянии с веткой, HEAD, состоянием рабочего дерева, текущей задачей и сводкой handoff, а затем таблицу задач, например —

```
Task table: 1) ...
```

**❌ Ничего не происходит?** Проверяйте по порядку:

1. Каким ИИ вы пользуетесь? Claude Code → `~\.claude\skills\baton\SKILL.md`; Codex → `~\.agents\skills\baton\SKILL.md`; Cursor → `~\.cursor\skills\baton\SKILL.md` (установка пользовательского уровня создаёт все три)
2. Есть ли у проекта `.git`? (иначе `git init` + первый commit)
3. Команда ровно **clock in**, без ничего лишнего?
4. Есть ли у проекта `docs/ai_memory/`? (установка уровня проекта создаёт его)

### Шаг 4: Подключение к существующему проекту Baton (новая машина / новый ИИ)

На новой машине: установите git → `git clone` вашего проекта → скажите вашему ИИ:

```
clock in  или  continue work
```

Память, handoff и задачи приходят вместе с кодом. Продолжайте сразу — больше ничего устанавливать не нужно.

### Что делает однокнопочный скрипт (прозрачно)

| Режим | Делает автоматически |
|---|---|
| Пользовательский уровень | Копирует `SKILL.md` в глобальные папки скиллов всех трёх ИИ-инструментов (Codex / Claude Code / Cursor) |
| Уровень проекта | ① скелет `docs/ai_memory/` (с журналом ревизий + индексом архива) ② `.baton/config.json` ③ дополнение `.gitignore` ④ три зеркала скилла ⑤ три входных сегмента (`AGENTS.md` / `CLAUDE.md` / `.cursorrules`, никогда не перезаписывает ваши правила) |

Идемпотентно: повторный запуск никогда не перезаписывает ваши документы и правила; он лишь заполняет недостающее.

## 📁 Где живёт истина

```
project/
├── docs/ai_memory/            ← долговременная память (синхронизируется с Git, не зависит от ИИ)
│   ├── index.md               ← прочтите меня первым
│   ├── current.md             ← что происходит сейчас
│   ├── handoff_current.md     ← журнал handoff (последняя запись = истина)
│   ├── state/                 ← tasks.json, archive_index.json, project_state.json
│   ├── knowledge/             ← tech_decision.md, pit_experience.md
│   ├── ui_spec/               ← дизайн-спецификации
│   ├── daily_log/             ← дневные журналы
│   └── agent_metrics/YYYY/MM/index.html  ← месячный дашборд
└── .baton/                    ← локально для машины (gitignored кроме config.json): конфигурация, метрики, доказательства
```

## 🛡️ Безопасность и принципы

- Опасный git (force push / reset --hard / рискованный clean / несанкционированный rebase) не существует
- Синхронизации только ff-only; расхождение останавливается и сообщается; конфликты никогда не разрешаются автоматически
- Учётные данные никогда не попадают в Git / память / метрики / журналы
- История только дополняется или помечается «заменено» — никогда не перезаписывается
- «Готово» = механическое доказательство (удалённый SHA + запись о публикации), а не заявление
- Экономия токенов — цель первого порядка: сначала индекс, модели по риску, ограниченные выводы, никаких лишних вызовов
